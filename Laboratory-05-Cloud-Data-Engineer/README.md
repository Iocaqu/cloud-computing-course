# Laboratory Activity 5: Mission 5 – The Cloud Data Engineer

## Mission Overview
In this lab, I was temporarily reassigned to the Cloud Data Engineering Team at CloudNova Technologies. The mission was to move beyond traditional Block and File storage and deploy an S3-compatible Object Storage server using MinIO, an open-source tool, running in Docker on a KillerCoda Playground. The goal was to stand up a working object storage environment, create a secure bucket named `client-photos`, and upload a test file to prove the setup works — a proof of concept for a client building a photo-sharing application that needs to store millions of user-uploaded images.

## Objectives
- Differentiate between Block, File, and Object Storage.
- Deploy an S3-compatible Object Storage server (MinIO) using Docker.
- Access a cloud service via a web interface using port forwarding.
- Create a storage bucket and upload objects (files) to the cloud.
- Document cloud storage operations using Markdown.
- Continue expanding a professional GitHub Cloud Computing Portfolio.

## Tools Used
- Docker
- MinIO (S3-compatible object storage server)
- KillerCoda Ubuntu Playground
- GitHub
- Markdown

## Skills Learned
- Distinguishing Block, File, and Object Storage and when to use each.
- Deploying a containerized service with Docker, including port mapping and environment variables.
- Accessing a service running in a remote sandbox through port forwarding.
- Creating a storage bucket and uploading objects through a web console.
- Writing clear technical documentation in Markdown.
